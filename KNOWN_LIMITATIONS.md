# Known limitations — incomplete development preview

This is **not the complete 79-layer product** and must not be presented as a production security suite. The coverage manifest records full requirement gaps even where a narrower implementation runs.

Major unfinished capabilities include packet flood mitigation, packet anti-spoofing/malformed filtering, validated threat-IP/domain enforcement, DNS rebinding defense, established network IDS integration, evil-twin analysis, browser credential-read telemetry, bulk-copy/exfiltration attribution, keylogger inspection, comprehensive vulnerability matching, trusted application auto-updates, off-device log shipping, and automatic post-update regression testing.

Windows event coverage depends on existing channel/audit settings. Security-log detectors query their required system audit subcategories and remain unavailable when required settings cannot be verified. Per-user exclusions can still restrict events. A subscription alone does not prove full event coverage. Channels are not silently enabled. TCP and bound UDP endpoint tables poll and can miss short-lived activity. UDP bound sockets do not prove per-packet UDP destinations or attack traffic. Neighbor-cache observations include IPv4/IPv6 from MSFT_NetNeighbor where Windows exposes them, falling back to IPv4-only ARP if that provider is unavailable. Neighbor MAC changes are heuristic and confirmed twice, not proof of spoofing. Bluetooth radio discoverability and connectability are observed via the native API when available, but pair authentication and remote connection attribution are not certified. Normal administrative changes, software installs, sync tools, legitimate address copies, and regular network clients can trigger heuristics.

Default baseline hardening is limited to AutoRun. Optional separately consented malicious-domain blocking uses OTS-owned Windows hosts entries, not a network firewall. OTS does not replace firewall policy or disable Defender. OTS can install bounded, five-minute, exact-source **inbound deny** rules after many already-blocked 5157 events when Security audit policy and Windows Firewall COM access permit it. This reactive rule path neither replaces default firewall enforcement nor constitutes SYN/UDP/ICMP volumetric flood mitigation. Rules are normally removed when expired, on stack OFF, or on service restart; a hard crash can leave a persistent rule until service recovery. See docs/SECTION_A_NETWORK_EVIDENCE.md. The blocked counter does not count Windows blocks as OTS blocks. ON cannot make unavailable capabilities operational. Main dashboard remains Partially Protected.

Section B local canaries are now monitored for content tampering and Windows 4663 reads where an active File System success-audit policy, decoy SACLs, and event delivery exist; no broad audit policy is enabled. DNS canaries depend on actual Windows DNS Client events. The honeypot is bound to loopback only with bounded resources and no automatic IP ban. Off-machine canary monitoring, externally reachable honeypots, real-hardware auditing reliability and malicious-process attribution guarantees are not verified. See [the deception implementation notes](docs/DECEPTION.md).

Section C adds conditional native Defender Network Protection event monitoring (1125/1126), cautious Windows security event ATT&CK technique hypotheses, TCP/UDP process-associated socket snapshots, DHCP/WLAN BSSID and cipher change alerts, additional SMTP port monitoring, RDP/remote-support service inventory, and monotonic/HTTPS Date clock comparison. These are detection/visibility capabilities, not a bundled independent packet IDS. Native Defender signatures and event subscriptions are controlled by Windows; full rule validation, packet-level rogue DHCP and evil-twin attestation, short-lived UDP peer attribution, external exposure testing, and physical Windows 10/11 qualification remain incomplete. HTTPS Date may require outbound Internet access and is not signed secure time. See docs/SECTION_C_NETWORK_VISIBILITY.md.

Desktop balloon alerts require the running GUI and can be suppressed by Windows notification policy. User-session monitoring is opt-in and stops when the GUI closes; settings are currently per-session. Camera/microphone registry observations are incomplete. Browser audit inventories only default Chrome/Edge extension directories. Background Downloads, temporary-folder and removable-file scan requests use installed Microsoft Defender, which alone applies its configured remediation/quarantine and recovery policy. OTS cannot infer a clean verdict from the scanner process exit code. New scans can miss transient, inaccessible, linked or over-budget files; some files may disappear or change before scanning.

Logging is bounded and HMAC-chained, but end-to-end segment verification and durable event counters are incomplete. Counters reset at service startup. Local administrators remain trusted. Resource governor uses budgets, battery intervals, cached heavy inventories, and service CPU/memory backoff; adaptive disk scheduling is incomplete. Layer elapsed times are real; per-layer memory is not fabricated.

Encrypted archives support reports and selected-folder file backups, with a 60 MiB / 5,000-file limit and verified restoration into a new folder. Empty directories, links, ACLs, full-system images and scheduled general backups are not preserved. External shipping remains incomplete. Quarterly report scheduling lacks durable historical trend storage. Recovery kit is not bootable media. Full layer-by-layer configuration controls are unfinished.

Installer is unsigned; trusted update delivery requires a valid signing identity. Upgrade stops the previous protection instance and requires reactivation. Installer transaction rollback after arbitrary interruption, full reboot/chaos tests, unprivileged IPC attack tests, and real Windows 10/11 hardware validation require more evidence before final release. CI Server 2025 evidence does not imply Windows 10/11 passed.


**GitHub source archive caveat:** Older history tracked a setup EXE using Git LFS, which could appear as a non-executable 134-byte pointer in historical source archives. The current source tree intentionally has no compiled installer or LFS-backed EXE. Download the compiled installer only from GitHub Release Assets, not the auto-generated Source code ZIP. The compiled Release ZIP has a real `installer/` folder. Installer execution on the user's specific Windows 11 Home device is not yet verified.


The service now authenticates retained JSONL/gzip event entries with the protected HMAC key on startup and continues the chain across new restarts. Earlier versions seeded new chains on startup; their historical discontinuities are reported rather than silently treated as proof of deletion. The 20-segment retention cap, absence of external tamper-evident anchoring and administrator trust boundary still apply. Host hardening audits are read-only indicators for UAC, DEP, LSA protection and explicit SMBv1 server disablement; unknown values are **not** evidence of protection. These additions do not implement missing network filters or complete all 79 layers.

Feodo Tracker optional public C2 IPv4 data is fetched over HTTPS at most every 15 minutes, strictly bounded, and accepted only while its own timestamp is less than 24 hours old. Network outages, stale/empty/malformed feeds, and untrusted HTTP redirects cause fail-closed **monitoring unavailable** (not traffic blocking). This feed is not digitally signed and supplies no domain list, IDS signatures, or IPv6 indicators. Sampled established TCP destinations are compared; a fresh match can trigger a reactive five-minute exact-destination outbound rule (16 maximum), not full-feed preemptive blocking, malware confirmation, guaranteed termination of established sessions, or proof of actual packet drops. Source terms are at https://abuse.ch/terms-of-use/ .

Layers 31/34 now process real Security event 4663 file-read metadata, with privacy-bounded in-memory file-path hashes. Windows emits these events only if Audit File System success auditing **and matching SACLs** are already configured for the observed files. OTS does not enable a system-wide file audit or alter file SACLs, as indiscriminate enablement can overload Security logs. If no valid audited events arrive, these layers report unavailable, not operational. A burst of reads does not prove a copy, credential theft, network exfiltration, or malware.

Layer 8 optionally recognizes a public-to-private DNS answer transition for an external FQDN from actual Windows DNS Client Operational Event 3008 query results (when the channel is enabled). It does not prevent DNS rebinding; DNS-over-HTTPS, private resolver traffic, missing events, and split-horizon DNS are significant limits. The engine does not alter DNS settings or trust zones. Startup UI size is bounded to the primary Windows working area, with scrollable content; physical multi-monitor/DPI tests remain necessary.

Layers 40 and 42 now have stronger read-only audits: TCP Docker management port candidates 2375/2376 are classified by local bind address, but port binding is not proof that Docker owns the listener or that its API is publicly reachable. OpenSSH parsing honors first-value global directives, marks Include/Match configurations unverifiable, and avoids treating unconfigured settings as safe. OpenSSH effective sshd -T, custom -f launch options, administrators_authorized_keys ACLs, Docker named pipes, WSL2 port forwarding, actual container permissions and exposed publish rules are not yet tested.

## Section D development branch — 2026-10-27

Host and endpoint checks have been expanded to observe scheduled-task definitions, loaded-user Run keys and multi-profile browser extension directories; Windows PnP driver signing flags; account/privilege and TaskScheduler/WMI events; service-side loaded-user camera/microphone consent timestamps; loaded-user proxy and update-source policy; BCD options; Docker daemon TCP configuration and loaded-user WSL distros. Mining signals require sustained CPU plus corroboration; 4663 bulk file reads may be correlated by PID to observed public TCP but do not prove uploaded data. Defender malware event names may indicate a known keylogger; OTS **does not** enumerate input hooks or detect arbitrary keyloggers.

These are narrower monitoring capabilities only. The GUI user-session collector (including clipboard monitoring) still stops when the GUI closes; the separate service-side privacy registry check is not complete camera/microphone stream auditing. Layer 31/34 must remain unavailable unless the required actual 4663 telemetry exists and SACLs are present. Initial file-integrity baselines are not publisher-trusted or durable. Physical Windows hardware tests, acceptance coverage and trusted-release signing remain missing. See docs/SECTION_D_IMPLEMENTATION.md.

## Section I limitations (layers 75–79)

Section I introduces a public HTTPS URLhaus-derived domain list, bounded background Defender scanning, WMI device-change alerts, file operation and ransomware-canary heuristics, and conservative TCP connection-timing detection. See [Section I implementation and acceptance](docs/SECTION_I_IMPLEMENTATION.md). These mechanisms remain limited and **not independently certified**.

- **75:** Blocking is OFF by default and requires an administrator confirmation. The public domain-feed mirror is **unsigned**; freshness and format validation are not publisher authentication. The feed currently declares a 12-hour expiration. Managed hosts entries cover a maximum of 1,000 exact names; DoH and direct-IP communication can bypass them. Missing/corrupted hosts state or external edit conflicts can prevent policy activation/recovery; report such failures rather than claim success. A custom administrator-managed allowlist is available.
- **76:** Requires a working local Microsoft Defender scanner. It submits background file scans, but misses transient files and cannot independently certify verdicts. Defender, not OTS, decides quarantine/remediation; consult Windows Security Protection History. Watcher overflows and queue drops are surfaced.
- **77:** WMI USB change events may be delayed or missed. Device classifications are best-effort and no input device is ever disabled or blocked.
- **78:** FileSystemWatcher events are best effort; named ransomware canaries require prior provisioning. Normal bulk operations can look suspicious. No reliable process attribution, safe full-scale rollback, or guaranteed timely prevention is claimed.
- **79:** Periodicity analysis observes only recurring TCP connections sampled by the service, not all network traffic or UDP. Familiar periodic processes are suppressed to reduce false positives but may conceal compromised software; jitter can evade the heuristic.

Windows Server 2025 CI builds, installer, upgrade, rollback and uninstallation tests do not establish real Windows 10/11 hardware qualification or guarantee security efficacy.

## November 13, 2026 security-hardening update

The DNS rebinding observation now treats mixed public/non-public DNS responses and special-use address destinations as potentially suspicious *after* an observed public-only baseline. It remains a warning-only sensor dependent on Windows DNS events; it cannot prevent browser/DNS rebinding or observe encrypted DNS traffic. The encrypted off-device log export refuses symbolic-link/junction directory ancestors and linked existing delivery receipts to reduce false off-device delivery claims. This is a best-effort user-space check, not a guarantee against concurrent filesystem swaps by an administrator. Physical Windows 10/11 and UNC/removable-volume qualification remains outstanding.

Manual preview publication now depends on a full-history Gitleaks scan using the reusable publication-security workflow. Earlier scans reported unresolved potential findings; these must be investigated, not silenced. The scan cannot attest Git LFS payloads, binary internals or old Release assets.

The pure IP-header parser now rejects additional malformed TCP/IPv6 fragment structures and records truncated captures as unsupported where appropriate. It is still **not** connected to live Windows Filtering Platform packets or an anti-spoofing block decision. The bounded Security Event 5157 source monitor now recovers after its old source histories expire even when saturated, but it still does not mitigate SYN/UDP/ICMP packet floods. CI dependency-inventory validation detects an absent/empty inventory, not all possible errors or all categories of supply-chain compromise.

The opt-in NuGet OSV advisory audit now follows per-package continuation tokens for at most four bounded batch requests. When tokens repeat, a response is malformed, or a valid result exceeds the request budget, OTS reports an incomplete result rather than a clean verdict. No installed-application inventory or independent advisory correctness attestation is implied. User-authorized package identifiers/versions are transmitted to OSV only when the user runs the check.

Ransomware-like file-change observations are now reset when delivery timestamps run backward, reducing stale-state suppression after a clock change; this does not provide an atomic log clock, attribution of the writer, packet visibility, automatic file rollback or reliable malware classification.

Encrypted-report and selected-folder-backup code uses best-effort managed-buffer zeroization and size checks on an open archive stream. This does not guarantee clearing copied plaintext strings, OS filesystem caches, crash dumps, or data retained by operating-system memory management. Backup functionality still does not provide whole-system images, ACL/links preservation, or tamper-proof off-machine storage.
